Three design directions for the reconciliation tool

Each concept shows the same four screens with the same illustrative data. That data is the engine's real output on the repository's synthetic test packs, so every name, PAN and figure is invented. The concepts use only what the tool does today and touch no production code. Each one is a single file that works offline.

A · Working papers

The screens look like the firm's own audit file. Each finding is a ruled schedule, and the difference is underlined with the accountant's total rule. Totals sit on one footing line instead of a row of cards.

Type
Bahnschrift for headings and figures, Segoe UI for text
Spacing
4 px base; 24 px page gutters
Navigation
Top masthead; the Client file has an index of documents on the left
Tables
Ruled, 9 px cell padding, figures right-aligned
Status
Square outlined marks, like a stamp

Advantages

  • The most distinctive look, and it speaks a CA's language: schedules, footings, the total rule.
  • Figures are the easiest to read of the three.
  • Reads top to bottom like a file you sign off.
  • Cheapest to build, because it is closest to today's code and the restyle already started.

Disadvantages

  • A client with 27 findings is a long scroll of stacked boxes, which is the same repetition the current screen has.
  • The two figures are read top to bottom, not side by side.
  • Fewer findings fit on one screen.

B · Matching desk

This uses the pattern of bank reconciliation software. The two documents face each other and the difference sits in the gutter between them, each with its own source. The list of findings stays on screen while you decide one at a time.

Type
Segoe UI Variable for text, Cascadia Mono for figures
Spacing
4 px base; 16 and 24 px inside panes
Navigation
Sidebar on the left; a bottom tab bar on phones
Tables
Hairline rules, 44 px rows, no fills
Status
A small square plus a word, so status never relies on colour alone

Advantages

  • Each disagreement is visible at a glance: first document, difference, second document, and where each figure came from.
  • Fastest to work through: arrow down the list, press 1, 2 or 3, and move on.
  • Grouped by the document to fix, without repeating headings on every card.
  • On a phone it becomes a list, and tapping a finding opens it.
  • The Worklist gets the same year-on-year side-by-side view.

Disadvantages

  • The full three-pane view needs a wide screen (about 1180 px). Tablets lose the document pane and get a dropdown instead.
  • Shows one finding at a time, so it gives less of an overview than A or C.
  • Findings with more than two figures fall back to a plain list.
  • The biggest rebuild: new layout and selection state in the Client file.

C · Workbook

A spreadsheet, the tool CA staff already live in. Gridlines, sheet tabs at the bottom, and arrow keys that move from cell to cell. A source bar sits where a formula bar would be and names the file and place of the selected figure.

Type
Segoe UI throughout, 13 px, with tabular figures
Spacing
30 px rows; 8 px cell padding
Navigation
Sheet tabs at the bottom; each open client becomes a tab
Tables
Full gridlines, frozen header and row numbers, filters under the headings
Status
Lightly tinted cells with words

Advantages

  • No learning curve for staff who are fluent in Excel.
  • The densest of the three: a whole client file on one screen.
  • The source of any figure is one arrow key away.
  • Several clients can be open as tabs at once.

Disadvantages

  • Weakest on a tablet or phone: the sheet scrolls sideways.
  • It looks editable, so staff may expect formulas, pasting and changing figures, none of which the tool should allow.
  • Long labels and the rule basis are cut off until you open a row.
  • A spreadsheet-style grid is the hardest of the three to make work with screen readers.

Recommendation: B, Matching desk

The tool does one job: show where two documents disagree, to the rupee, and say where each figure came from. B is the only direction where that job is the layout itself, with the two sources facing each other and the difference between them. A reviewer can work through 27 findings without losing their place, and every decision sits next to the figures it is about. That fits a filing-season rush, where speed and confidence in each finding matter more than overview.

Two ideas from the other directions would improve B cheaply. A's footing line and total rule could set the totals, and C's source bar could show the source of whichever figure has keyboard focus. If B's rebuild cost is too high before the 30 October demo, A is the safe interim step, because its styling is already half done.

The patterns come from widely used professional software I already know: bank reconciliation matching screens, audit working-paper tools with tick marks and the total rule, keyboard-first triage inboxes, and spreadsheets. I didn't run new web research for this; tell me if you want it. Nothing in this folder is wired to the engine, and decisions and classifications made here are not saved.
