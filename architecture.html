Recon Tool architecture

Reconciliation & Verification Tool for Indian CA firms, Tool 1. This map reflects the repository as of 26 October 2026 (after SPEC-006, with SPEC-007 in progress). It comes from go list imports and each package's doc.go.

Server side (may use network) Engine side (built) Data & content files Planned (only doc.go so far)

How one run flows

  1. Staff upload files in the browser. internal/api starts a separate recon-engine process with os/exec and reads its JSON output. Exit codes: 0 no findings, 1 findings, 2 input or rule error, 3 internal.
  2. ingest opens each file with the json, csv or xlsx adapter. Adapters know file syntax only.
  3. profile matches exactly one format profile (built in, or an office profile taught on the Teach layout screen) and extracts named facts and records with locators.
  4. store keeps drafts, facts, records and run snapshots in encrypted SQLite.
  5. engine selects the active rules for the tax year (optionally one comparison type) and evaluates each with its check type.
  6. findings words every broken edge from fixed templates. Decisions (Fix, Not an issue, Ask client) are stored append-only against stable finding IDs.
  7. Separately, newheads compares two years of ledger CSVs and produces Worklist items for staff to classify.

Invariants the code enforces

No network in the engine. The engine-side package list is in archtest_test.go. The guard writes build/engine-deps-*.txt and engine-symbols-*.txt as proof. Third-party edges to parse-only packages need an entry in allowedNetworkImports (ADR 0001).
Import direction. Engine-side packages must never import api, authz, export or web. money and period import only the standard library, and domain adds only those two.
Determinism and money. Engine-side directories may not read the clock or use randomness. Money directories may not use floating point; all amounts are int64 paise.
Offline, single machine. Pure-Go SQLite, the UI embedded with go:embed, no CDNs or services. Staff reach recon-server over the LAN.
